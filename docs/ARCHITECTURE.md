# Architecture

This document describes how the Aperture Mesh Observatory is assembled: the reference, sensing and
act/truth planes, how data flows, and where the coherence comes from.

## 1. Design principle

> Combine independent, inexpensive receivers into a single instrument whose measurements are coherent
> in **time**, **frequency**, and — where the physics allows — **carrier phase**.

Coherence is layered, and each layer is independently useful:

| Layer | Achieved by | Enables |
|---|---|---|
| Amplitude / spectrogram | nothing special | coverage, duty cycle, interference detection |
| Sample-time coherence | shared clock **or** correlation alignment | bandwidth aggregation, long-baseline TDOA (with absolute time) |
| Carrier-phase coherence | shared clock **+** reference injection | short-baseline bearing / direction of arrival |

## 2. Planes

### 2.1 Reference plane

```
GNSS antenna ──▶ Web-888 GPS module ──PPS──▶ PID loop ──▶ Si5351 ──▶ clock-out SMA
                                             (Kp 1.4, Ki 0.15, Kd 0.01)
```

- The Web-888's ADC clock is generated by an Si5351 synthesiser (CLK0, 122.88 MHz for HF), not directly
  by the TCXO.
- PPS from GNSS disciplines the Si5351 through a PID controller — the manufacturer's *"poor man's GPSDO"*.
- The governed PLL can also drive the **clock-out SMA**, giving a GPSDO-grade reference for other radios.
- A reference **clock-in** option exists, allowing the Web-888 itself to be disciplined externally.
- Reading of the **GPS PPS counter** is exposed for precise software timestamping.

**Caveat:** the manufacturer warns that enabling clock-out degrades the Si5351 phase noise; it is off by
default. Phase-noise-versus-accuracy is an explicit project risk (see the proposal).

### 2.2 Sensing plane

- **RTL-SDR #0** — direct USB. ~2.4 MHz instantaneous bandwidth, 8-bit, receive-only, native 28.8 MHz clock.
- **RTL-SDR #1** — reached over the network via `rtl_tcp`; may be co-located or remote (LAN/Tailscale).
- **Web-888** — HF (≈0–61 MHz) and VHF (≈118–150 MHz) monitoring; multi-user, 13 DDC channels of 12 kHz
  plus two spectrum channels. **Cannot receive the 902–928 MHz LoRa band.**

Typical channel plan (US ISM):

| Channel | Centre | BW | SF | Protocol |
|---|---|---|---|---|
| Meshtastic long-fast | 906.875 MHz | 250 kHz | 11 | Meshtastic |
| MeshCore (US) | 910.525 MHz | 62.5 kHz | 7 | MeshCore |
| Reticulum LoRa (US) | 911.0 MHz | 125 kHz | 10 | Reticulum / RNode |

### 2.3 Act / truth plane

- The spare **MeshCore modem** is the only transmitter and the only *protocol-aware* device.
  - **Ground truth:** it decodes real packets, giving identity, timestamps and payloads that can be
    correlated against what the SDRs observe.
  - **Calibration beacon:** commanded from the Linux host, it transmits compliant known signals from a
    known position — the source-of-opportunity analogue of Laakso's injected reference.
  - **Relay interface:** eventually the radio front end of a spatially-aware relay.

## 3. Data flow

```
 capture                pre-processing            measurements           products
 ───────                ──────────────            ────────────           ────────
 RTL #0  ─┐             DC removal                RSSI / SNR            coverage map
 RTL #1  ─┼─▶ IQ ──▶    channelisation ──▶        packet detect ──▶     node proximity map
 Web-888 ─┘             (DDC)                     arrival time          bearing (later)
                                                   phase difference      collision/interference log
 MeshCore modem ─▶ decode log ─────────────────▶  identity/timestamp ─▶ unified live view
```

The modem's decode log is the **label** for what the SDRs measure. Where the SDRs see energy but the
modem decodes nothing, that is interference, or a signal outside the protocol, or a collision.

## 4. Where coherence comes from

### 4.1 Time / frequency (long baseline)

- Absolute time from GPS PPS; stable frequency from the disciplined clock.
- Receivers at separated sites timestamp packet arrival; the difference in arrival time, with known
  receiver positions, yields a position hyperbola.
- Sample resolution at 2.4 Msps is ≈417 ns ≈125 m of path — poor for a tabletop, fine for kilometre
  baselines. Fractional interpolation improves it modestly.

### 4.2 Carrier phase (short baseline)

- A common sampling clock makes the *sampling* coherent; a known reference signal injected into each
  channel removes the remaining per-channel **carrier-phase** offset (the tuner PLL lands in an arbitrary
  phase on each retune).
- With phase calibration, the phase difference between elements gives a bearing.
- Drift requires periodic recalibration; the source work measured <1°/minute.

## 5. Software decomposition (intended)

```
src/
  capture/        dongle + rtl_tcp + Web-888 acquisition, time-stamped IQ
  channelise/     down-conversion, filtering, channel plan
  measure/        RSSI/SNR, packet detection, arrival time, phase estimation
  demod/          LoRa PHY (gr-lora_sdr integration), protocol framing
  truth/          MeshCore modem driver, decode log, calibration-beacon control
  fuse/           multi-receiver combination, TDOA, bearing, dedup
  serve/          unified live view (SSE), logs, dataset writer
  relay/          spatially-aware relay logic (later phases)
```

This mirrors the existing `sdr-decode` suite (USB receiver, network receiver, protocol decoder, combiner)
and extends it with the reference plane, truth plane and fusion.

## 6. Failure modes to design against

- **Sample loss** silently breaks correlation-based alignment — always verify stream continuity.
- **Clock-out phase noise** can be adequate for TDOA but inadequate for tight DOA.
- **Retune phase jumps** invalidate phase calibration — recalibrate after every retune.
- **Gain mismatch between dongles** biases amplitude-based measurements — calibrate per board.
- **Multipath** corrupts bearing far more than it corrupts proximity.
